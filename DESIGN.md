# Grepit Design System v5

# Core Product Thesis

Grepit is not a SaaS dashboard.
Grepit is not a chatbot.
Grepit is not an AI wrapper.

Grepit is a cinematic spatial intelligence system for understanding software architecture.

The interface should feel:

* operational
* alive
* dynamic
* premium
* infrastructural
* intelligent
* deeply responsive
* spatially coherent
* meticulously engineered

The product should feel:
crafted with obsession.

Not:
assembled from components.

---

# The Product Feeling

Users should feel:

* immersed
* oriented
* aware
* guided
* powerful
* calm
* technically confident

The interface should feel:
like a living operational environment.

Not:
like browsing pages.

---

# The Core UX Direction

The UX direction should combine:

* Linear responsiveness
* Arc spatial continuity
* Emil Kowalski motion softness
* Apple interaction choreography
* Datadog information density
* Figma canvas navigation
* modern observability tooling ergonomics

WITHOUT visually copying any of them.

The goal is:

# operational cinematic UX.

---

# 1. Spatial Intelligence

Repositories should feel:
navigable.

Not:
like folders.

The user should feel:
inside architecture.

# 2. Dynamic Interfaces

Systems should:

* pulse softly
* illuminate relationships

alive.

# 3. Motion As Understanding

Motion exists to:

* preserve orientation
* explain causality
* guide attention
* communicate hierarchy
* maintain continuity
* reinforce mental models

Animation is NOT decoration.

---

# 4. Premium Through Precision

Premium feeling comes from:

* interaction quality
* responsiveness
* rhythm
* continuity
* timing
* hierarchy
* restraint
* consistency

NOT:
visual excess.

---

# 5. Cognitive Clarity

Every interaction should:
increase understanding.

Every interaction should:
reduce uncertainty.

# Architecture Interaction Choreography

# Hover

Hovering a node should:

1. softly illuminate connected systems
2. trace dependency paths progressively
3. subtly dim unrelated systems
4. reveal metadata progressively

Timing:
120–180ms.

Never:
instant harsh highlights.

---

# Click

Clicking a subsystem should:

1. preserve current orientation
2. zoom contextually
3. expand related systems progressively
4. animate dependency focus
5. update context panel with staggered reveal

Motion duration:
320–500ms spring.

---

# Traversal

Selecting request paths should:

1. animate request flow progressively
2. reveal operational chain
3. illuminate execution order sequentially

Reference feel:
network observability tooling.

---

# Conversation UX

Chat is:
assistive intelligence.

NOT:
the primary interface.

---

# Conversation Rules

Questions should modify:
the entire environment.

Example:
asking about authentication:

* highlights auth systems
* traces auth request flow
* reveals related middleware
* updates onboarding route
* contextualizes architecture visually

The environment itself should react intelligently.

# Motion System

# Motion Philosophy

Motion should feel:
soft, physical, intelligent, and infrastructural.

Primary references:

* Emil Kowalski motion systems
* Apple interaction continuity
* Arc transitions
* Linear responsiveness

---

# Motion Rules

Use:

* spring-based motion
* layered easing
* anticipation
* overshoot restraint
* stagger orchestration
* velocity-aware interpolation

Avoid:

* abrupt fades
* generic slide-ins
* robotic timing
* linear easing
* bounce-heavy motion

---

# Motion Timing System

# Hover States

120–180ms.

---

# Context Expansion

280–420ms spring.

---

# Large Spatial Transitions

500–900ms progressive orchestration.

---

# Request Traversal Animation

600–1200ms sequential illumination.

---

# Page/Environment Transitions

400–700ms layered interpolation.

---
